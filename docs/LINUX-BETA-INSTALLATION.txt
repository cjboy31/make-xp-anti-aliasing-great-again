MAKE XP ANTI-ALIASING GREAT AGAIN - 0.2.0-linux-beta.1
Native Linux x86_64 beta for X-Plane 12 / Vulkan

THIS IS A LINUX BETA
Includes the native lin.xpl controls, Linux Vulkan .so layer, SMAA 1x,
FXAA 3.11 and experimental native TAA. It uses no FSR, upscaling or frame gen.
Native Linux build, CPU/IPC, injected Vulkan readback and package/activation
checks are automated. Actual Linux X-Plane flight operation and visual quality
still need community validation. Windows screenshots are examples from Windows;
they do not prove a Linux result. Different native scene signatures bypass.

REQUIREMENTS
- Native Linux x86_64 X-Plane 12.4.4, not Wine/Proton or macOS.
- A working Vulkan 1.3 graphics driver and Vulkan loader, native OpenGL runtime,
  glibc 2.35+, libstdc++6 and OpenSSL 3 libcrypto.so.3.
- Python 3.10+ for setup. Optional python3-tk provides a graphical folder picker.
- Write access to this simulator's Resources/plugins and your normal per-user
  Vulkan data directory. No compiler, SDK, root access or sudo is needed.
Debian 12/13 and comparable modern distributions are initial targets; individual
drivers/GPUs require beta reports. ARM, HDR/PQ, VR and distinct multi-view paths
are not validated. The reported RX 9060 XT and Radeon 8060S systems have not
been flight-tested here. Install a suitable distribution GPU driver normally.

INSTALL
1. Close X-Plane normally. Download the Linux-x86_64.tar.gz beta release asset.
2. Extract ALL files together, then read this file before installing.
3. Open a terminal in the extracted folder and run:
     ./install.sh
   Select the X-Plane root containing X-Plane-x86_64. If you prefer a path:
     ./install.sh --simulator "/path/to/X-Plane 12"
   If executable permission was lost during extraction, the equivalent is:
     python3 install-linux.py --simulator "/path/to/X-Plane 12"
4. Use your normal X-Plane or third-party launcher. You do not need this setup
   program open. Choose Plugins > Native AA > Open AA controls in the sim.
5. Load a flight and check for fresh AA ACTIVE or TAA ACTIVE. A loaded plugin
   or selected mode alone does not mean that rendering is active.

The installer writes only Native AA files in the selected simulator and its
own per-simulator manifest in ${XDG_DATA_HOME:-~/.local/share}/vulkan/implicit_layer.d.
Other Vulkan manifests are retained. External drives work if mounted at the same
location and permitting executable files. Do not run the simulator/setup as root.
Steam/Flatpak/container launchers must expose both the plugin and per-user layer
to their Vulkan runtime. Sandboxed launcher discovery is not validated here.

SIMULATOR SETTINGS AND CONTROLS
- Render/input scale: Full. Keep your preferred output resolution and UI scale.
- Native simulator FXAA: Off for comparisons. Native MSAA may remain enabled;
  start with 2x if desired and watch GPU frame time/memory.
- Do not use another FSR/DLSS/XeSS/NR/FG scene reconstruction layer simultaneously.
- SMAA High is the default. Try FXAA for spatial smoothing, or experimental TAA
  for accumulation of jittered native geometry. Adjust blend/subpixel/history
  controls live. TAA uses estimated camera/depth motion and can soften or trail
  moving content; general native object/cloud vectors are unavailable.
- Reset TAA history after visual discontinuities. New motion assistance,
  dedicated shimmer improvements and combined-AA modes are a later update.
- Choices save to Output/preferences/NativeAA.ini. No controller or camera
  bindings, resolution settings or UI scale are changed by the installer/plugin.

BETA DIAGNOSTICS
The renderer retains the exact validated SDR scene/shader/depth admission gates.
Linux may use a different scene signature; if it does, the layer must bypass
instead of modifying an unidentified image. Do not edit hashes or force a shader
override to hide a bypass. Report the current-session renderer log so the
different boundary can be investigated safely.
Logs: Output/NativeAA/renderer-<process>-<session>.log. Read the latest session.
Report distribution, kernel, GPU, driver/Vulkan version, X-Plane version, mode,
activity message and whether you used a sandboxed/Steam/third-party launcher.
Remove personal path details before posting logs. AA scratch is bounded, but
simulator/driver memory and per-GPU performance are separate.

UPDATE / DISABLE / UNINSTALL
Close X-Plane and install the newer Linux package into the same simulator root.
Obsolete unchanged owned files are removed; unknown/modified user files survive.
Use the live On/Off control for a comparison. To stop renderer discovery, close
X-Plane and set Resources/plugins/NativeAA/standalone.enabled to:
  NativeAAStandalone=0
To uninstall from this package folder:
  ./install.sh --uninstall --simulator "/path/to/X-Plane 12"
Uninstall removes unchanged recorded files and its own unchanged manifest.
Saved NativeAA.ini preferences and other plugins/layers are retained. Do not
change XDG_DATA_HOME between installation and uninstall; select the same mount.
Do not install this beta over a Windows Native AA inventory in a shared folder.
